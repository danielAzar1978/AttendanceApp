## Documentation Update Rules

Documentation is considered part of the codebase.

Whenever code changes, documentation must be reviewed.

---

### README.md Update Triggers

Update README.md when any of the following occur:

✔ New feature added

✔ New technology introduced

✔ Installation steps changed

✔ Deployment process changed

✔ Application startup process changed

✔ New important API endpoint added

✔ Authentication flow changed

✔ New external service integrated

Examples:

* Google Maps integration
* Manager Login
* Reports module
* Notifications
* Password hashing

---

### PROJECT_CONTEXT.md Update Triggers

Update PROJECT_CONTEXT.md when any of the following occur:

✔ New architectural decision

✔ New database table

✔ New database relationship

✔ New business rule

✔ New module

✔ New security model

✔ Significant workflow change

Examples:

* UserWorkLocations
* WorkLocations
* Role Management
* Shift Scheduling
* Approval Workflows
* GPS Validation Changes

---

### CODING_RULES.md Update Triggers

Update CODING_RULES.md when any of the following occur:

✔ New coding standard

✔ New project convention

✔ New architectural pattern

✔ New folder structure

✔ New development workflow

✔ New validation rules

Examples:

* Repository Pattern
* Service Layer Rules
* Authorization Standards
* Naming Conventions
* Error Handling Standards

---

### End Of Session Checklist

At the end of every major development session:

[ ] Review README.md

[ ] Review PROJECT_CONTEXT.md

[ ] Review CODING_RULES.md

[ ] Update Version if needed

[ ] Update Last Updated date

[ ] Commit documentation changes together with code changes

Documentation should always describe the current state of the project.
